# Stock Aggregator Server (SAS)

Фоновый сервис на .NET, который подключается к нескольким симуляторам бирж (криптовалютным/фондовым) по WebSocket, нормализует и дедуплицирует входящие котировки и сохраняет их в базу данных пакетами — все биржи обрабатываются параллельно, без потери данных при остановке.

Проект предоставлен исключительно в ознакомительных целях

## Что делает система, одним предложением

Множество бирж передают котировки одновременно → каждая котировка проходит дедупликацию → принятые котировки ставятся в очередь → единственный writer собирает их в пакеты и сохраняет в БД, даже при обрывах соединения, ошибках БД или штатной остановке сервиса.

## Конфигурация `appsettings.json`

| Настройка                       | Назначение                                                                     |
|---------------------------------|--------------------------------------------------------------------------------|
| `AggregatorSettings.Exchanges`  | Список бирж для подключения (имя, URL, тип биржи)                              |
| `StorageSettings.BatchSize`     | Максимум котировок за одну запись в БД                                         |
| `StorageSettings.FlushInterval` | Максимальное время ожидания перед сохранением неполного пакета                 |
| `StorageSettings.MaxRetryCount` | Количество повторных попыток при ошибке записи в БД перед отбрасыванием пакета |

## Как добавить новую биржу

1. Реализовать `IExchangeAdapter` для формата сообщений новой биржи (парсинг сырого JSON → `Quote`).
2. Забиндить через DI новый адаптер как `AddSingleton<IExchangeAdapter, NewExchangeAdapter>()`.
3. Добавить запись в `AggregatorSettings.Exchanges` с именем, URL и типом биржи. Это делается в `appsettings.json`

Больше ничего менять не нужно — супервизор, клиент, дедупликатор и слой хранения не зависят от конкретной биржи.

## Как поднять БД

1. Установить PostgreSQL, и создать пользователя с правами на создание БД и таблиц.
2. Указать креды postgre юзера в `appsettings.json` (`DefaultConnection`).
3. Выполнить команду в `cmd` или `консоли IDE`: `dotnet ef database update --project SAS.Infrastructure --startup-project SAS.Web`

## Компоненты

### `ExchangeSupervisorBackgroundService`
Точка входа конвейера приёма данных. Читает список настроенных бирж (`AggregatorSettings.Exchanges`) и запускает по одному `WebSocketExchangeClient.RunAsync(...)` на каждую биржу — все они выполняются **параллельно** через `Task.WhenAll`. Если соединение с одной из бирж обрывается, это никак не влияет на остальные.

При остановке сервиса, как только все циклы по биржам действительно завершились, этот сервис сигнализирует слою хранения, что новых котировок больше не будет (см. [Graceful shutdown](#graceful-shutdown) ниже).

### `WebSocketExchangeClient`
Отвечает за жизненный цикл подключения к одной бирже:
- Подключается к WebSocket-адресу биржи.
- Читает входящие сообщения в цикле, собирая фрагментированные WebSocket-кадры в единое сообщение.
- Делегирует разбор формата сообщений конкретной биржи объекту `IExchangeAdapter` (свой на каждую биржу), который парсит сырой JSON в нормализованный `Quote`.
- Передаёт каждую распарсенную котировку в `IQuoteProcessor.ProcessAsync(...)`.
- Если соединение обрывается по любой причине, автоматически переподключается с **экспоненциальной задержкой** (начиная с 1 секунды, удваивая до потолка в 30 секунд), чтобы нестабильная биржа не грузила систему бесконечными попытками и не оставалась без переподключения.

### `QuoteProcessor` (`IQuoteProcessor`)
Единая точка, через которую проходит каждая входящая котировка, независимо от того, с какой биржи она пришла:
1. Прогоняет её через `IQuoteDeduplicator.TryAccept(quote)`.
2. Если котировка отклонена как дубликат — увеличивает счётчик дубликатов в сервисе хранения и отбрасывает котировку.
3. Иначе — передаёт её в `IQuoteStorage.EnqueueAsync(...)` для сохранения.

### `QuoteDeduplicator`
Предотвращает повторное сохранение одной и той же котировки — это важно, поскольку одна и та же котировка может прийти дважды: от разных источников на одной бирже или при повторной доставке после реконнекта. Котировка считается дубликатом, если у неё совпадают `Source`, `Ticker`, `Price`, `Volume` и `Timestamp` с котировкой, уже виденной за последние **30 секунд**.

Реализация: `ConcurrentDictionary` для поиска за O(1) плюс `ConcurrentQueue`, фиксирующая время истечения каждой записи, чтобы устаревшие записи можно было удалять без полного сканирования кэша. Полностью потокобезопасна — рассчитана на то, что к ней будут одновременно обращаться циклы приёма всех бирж сразу.

> Важно: `CleanupExpired()` необходимо вызывать периодически (например, из небольшого фонового сервиса на таймере), иначе кэш будет расти неограниченно.

### `QuoteStorageBackgroundService` (`IQuoteStorage`)
Единая точка, куда попадают все принятые котировки, и единственный компонент, который обращается к базе данных:

- Внутри использует ограниченный `System.Threading.Channels.Channel<Quote>` (ёмкостью 10 000), настроенный на **несколько писателей, один читатель** — каждый путь обработки котировок с любой биржи может писать в канал конкурентно, а один фоновый цикл его вычитывает.
- Собирает котировки в пакеты для эффективной записи в БД: заполняет пакет до `StorageSettings.BatchSize`, либо сбрасывает его раньше, если прошло `StorageSettings.FlushInterval`, а котировок накопилось меньше — так данные не задерживаются надолго в периоды затишья.
- При ошибке записи в БД повторяет попытку с экспоненциальной задержкой (`2^retry` секунд), до `StorageSettings.MaxRetryCount` раз, прежде чем отказаться от пакета и посчитать его отброшенным.
- Предоставляет счётчики в реальном времени — `TotalSaved`, `TotalDropped`, `TotalDuplicates`, `LastBatchSize`, `LastBatchPause` — полезные для health-check или мониторингового эндпоинта. Они обновляются через `Interlocked`-операции, поскольку записываются из цикла хранения, а читаться могут из любого другого потока в любой момент.

## Модель конкурентности

| Этап                           | Конкурентность                              | Механизм потокобезопасности                                    |
|--------------------------------|---------------------------------------------|----------------------------------------------------------------|
| Подключения к биржам           | N бирж работают полностью параллельно       | Независимое состояние на каждое подключение (без общих данных) |
| Дедупликация                   | Вызывается конкурентно из потоков всех бирж | `ConcurrentDictionary` + `ConcurrentQueue`                     |
| Передача котировок в хранилище | Много писателей → один канал                | `Channel<Quote>` с `SingleWriter = false`                      |
| Сохранение пакетов             | Один читатель/писатель к БД                 | К БД обращается только один цикл, поэтому блокировки не нужны  |
| Счётчики статистики            | Пишет цикл хранения, читает кто угодно      | `Interlocked`-чтение/запись                                    |

Это значит, что добавление новой биржи — это просто изменение конфигурации: оно не требует правок логики синхронизации, поскольку все общие компоненты изначально спроектированы с расчётом на несколько конкурентных производителей данных.

## Штатная остановка (graceful shutdown)

Система спроектирована так, чтобы обычная остановка (SIGTERM, `Ctrl+C`, остановка службы) никогда не теряла уже принятую котировку:

1. Хост сначала просит остановиться `ExchangeSupervisorBackgroundService`. Циклы `RunAsync` реагируют на отмену и перестают открывать новые соединения/попытки переподключения.
2. Как только все циклы по биржам завершились, супервизор вызывает `IQuoteStorage.Complete()`, что завершает внутренний канал — это и есть основной сигнал «новых котировок больше не будет».
3. Цикл чтения `QuoteStorageBackgroundService` **не** останавливается по токену отмены хоста. Он продолжает вычитывать канал — включая всё, что уже накоплено в оперативной памяти, — пока канал не станет одновременно завершённым и пустым, собирая и сохраняя пакеты по ходу дела.
4. Финальное сохранение пакета выполняется с `CancellationToken.None`, чтобы остановка сервиса не могла прервать запись или её повторные попытки на середине.
5. Только после полного вычитывания канала цикл хранения завершается, позволяя хосту корректно закончить остановку.

Чтобы это работало правильно, `QuoteStorageBackgroundService` должен быть зарегистрирован в DI **раньше**, чем `ExchangeSupervisorBackgroundService` (хостed-сервисы останавливаются в обратном порядке регистрации — сервис хранения должен останавливаться последним), а `HostOptions.ShutdownTimeout` должен быть с запасом больше худшего по времени сценария повторных попыток (`MaxRetryCount` × backoff + `FlushInterval`).
